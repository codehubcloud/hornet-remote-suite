## 19.2 已采纳的架构决策

| ADR | 决策 | 理由与代价 |
|---|---|---|
| ADR-001 | 一个工作台，多独立协议进程 | 统一体验并隔离故障；需要监督、IPC与资源回收 |
| ADR-002 | 持久化配置、连接、通道、视图和任务分离 | 可靠恢复与连接复用；增加协调层 |
| ADR-003 | 核心离线可用，Agent/云/AI可选 | 避免基础连接依赖外部服务 |
| ADR-004 | Windows首先验证，平台按功能认证 | 原生图形与打印无法由Electron保证可移植 |
| ADR-005 | 采用成熟协议引擎适配，不自研X/RDP协议栈 | 降低协议开发量，但必须维护原生分发与兼容 |
| ADR-006 | 所有副作用任务明确幂等/结果未知 | 避免重复命令/打印或损坏文件；恢复UI更复杂 |

## 19.4 实施建议

按第18章先确定统一契约，并完成“主机→终端+文件→独立关闭→断线恢复”闭环。X11、RDP/VNC、LPD 是本产品核心技术风险，应在M0验证；高级IDE和AI后续接入现有资源和权限体系，不再创建旁路连接。

本设计共24章，目录见 [README](README.md)。第20章为唯一工程目录规范。
