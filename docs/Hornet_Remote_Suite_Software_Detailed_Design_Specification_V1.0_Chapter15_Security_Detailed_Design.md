# 15.11 数据加密设计

敏感数据：

-   密码
-   Token
-   License
-   私钥

采用：

使用成熟库的AEAD封装（例如AES-256-GCM），每次加密生成独立nonce并验证tag；密钥轮换与版本写入封装。不能仅指定AES-256而省略模式、完整性及密钥生命周期。

密钥：

使用系统安全存储。

# 15.12 通信安全设计

保护：

-   API通信
-   License通信
-   Update通信

# 15.25 桌面信任边界与默认策略

本地核心不要求Hornet云账户；SSO/JWT只作用于可选企业API。企业登录不自动授权远端SSH/RDP。JWT验证标准exp、iss、aud、签名算法与有效期；敏感refresh token只放凭据库，桌面OAuth采用系统浏览器及PKCE。

密码认证不是“客户端禁止弱密码即可安全”；远端账号策略由服务器执行。客户端保证不泄漏凭据、校验服务器身份、限制错误重试。主密码如需提供，应与OS凭据库区分：本期先提供OS凭据库锁定，跨设备主密码保险库作为24章兼容项，不能使用主密码字符串直接作为AES密钥。

未知主机首次显式核验，key变更阻断；凭据库不可用不降级明文。Renderer开启contextIsolation、sandbox，关闭nodeIntegration；导航和新窗口默认拒绝，外链仅允许经校验的scheme。

X11禁止开放无鉴权显示，按主机信任域隔离；VNC桥需token/origin验证；LPD默认不监听外网，来源白名单不是强认证。打印内容与桌面帧不进入诊断日志。应用锁定立即遮挡视图并阻止新输入/凭据读取；后台传输是否继续由明确策略决定，不能虚假承诺远端会话已登出。

插件签名仅证明来源，Node独立进程不是安全沙箱，按9章执行；AI黑名单不是授权机制，按10章绑定实际操作审批。远端交互shell的完整命令审计无法从按键流可靠重建，需要服务端审计/受控执行通道，UI不能宣称防绕过。

文件安全采用实际路径与授权根检查，包括符号链接、Windows junction/reparse point、UNC与路径大小写；远端浏览遵循账号权限，不将任意包含“..”的字符串一概视为攻击。
